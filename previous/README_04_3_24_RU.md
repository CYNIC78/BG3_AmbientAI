# AmbientAI b04.3.24 — «Фамильяр: нашёл, почему не видел»

Файл: `AmbientAI_b04_3_24_FamiliarDB.pak` · md5 `af0c87767e5eeed4c6097d58dda0780a`
База — 04.3.23 (`previous/`), фильтр лога из 04.3.22 внутри.

## Твой лог был прав, а мод — виноват

```
[AmbientAI] familiar idles: OFF | hops=0 skipped=0 last='-'
  no non-party character within 12 m - summon the familiar next to you and run the command again
```

Имп стоял в той же куче, что и партия, а список был пуст. Причина не в игре, а в моём коде:
список строился из пространственного индекса, а индекс **намеренно** пропускает всё, у чего есть
компонент `PartyMember`:

```lua
if ce ~= nil and ce.Transform ~= nil and ce.PartyMember == nil then   -- sweep
```

У связанного суммона (фамильяр Пакта Цепи) этот компонент **есть** — именно поэтому в
`IsRealPartyCompanion` и стоит проверка `Osi.IsSummon`. То есть индекс физически не мог его
увидеть, и команда честно докладывала «никого нет». Ошибка моя, не твоя.

## Что теперь

Суммоны берутся из базы, которая для этого и существует:

```lua
Osi.DB_PlayerSummons:Get(nil)   -- все активные суммоны игрока
```

Это не зависит ни от ECS-компонентов, ни от фильтров индекса. Индекс остаётся только для проверки
«не встать на людей», плюс `Osi.GetPosition` по каждому спутнику.

Команда теперь печатает коротко (у тебя строка стоит секунды, поэтому максимум 4 строки):

```
[AmbientAI] familiar idles: OFF | hops=0 skipped=0 last='-'
  DB_PlayerSummons: ok | rows=2 summons=2 inSpatialIndex=1
  CON_Familiar_Imp       3.3 m  summon=true partyComp=true
```

`inSpatialIndex` меньше `summons` — это и есть доказательство, что индекс их недо-видит, а мы их
всё равно находим. Если `DB_PlayerSummons` окажется `MISSING` или `rows=0` при живом импе — тогда
присылай, будем искать третий путь.

## Что делать тебе

1. Поставь 04.3.24, зайди в игру с вызванным фамильяром.
2. `!ambient_familiars` — пришли эти 2–3 строки (интересуют имена шаблонов и `rows=`).
3. Если хочешь посмотреть поведение: `!ambient_familiars on`, 2–3 минуты, `!ambient_familiars off`
   (можно и оставить включённым — состояние живёт в сейве).

## Честно про непроверенное

* Пойдёт имп по `Osi.CharacterMoveToPosition` пешком или полетит — проверяется только в игре.
* Как быстро движок сам подтягивает фамильяра назад к ГГ (может съедать часть дрейфа).
* Ведёт ли себя так же остальной сет фамильяров — список как раз это покажет.

## Стенд

`s37` переписан под реальную модель: **имп с компонентом `PartyMember`** (индекс его не видит) +
**квазит без компонента**. 5 прогонов подряд без флака:

| фаза | проверка | результат |
|------|----------|-----------|
| A | выключено | 0 перемещений |
| B | диагностика | `rows=2 summons=2 inSpatialIndex=1`, имп в списке с `summon=true` |
| C | включено, 240 с | 6–8 перемещений, 1.8–4 м от ГГ, минимум 1.76 м до людей |
| D | рядом враг | 0 |
| E | ГГ идёт | 0 |

`slowTicks=0`. На 04.3.23 тот же сценарий FAIL (имп не находится) — дискриминация есть.
Регресс 23 сценария по пак-файлу: ошибок Lua 0, все PASS.
